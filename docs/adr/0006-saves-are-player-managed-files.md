# Saves are player-managed, versioned files

Games are saved and loaded only when the player chooses to, and always as files on disk, never in browser storage. The player clears browser data when the browser closes, so anything kept there would be lost. Saving downloads a save file, and loading opens a file picker, which works in Firefox, the only supported browser. Every save file records a format version from the very first release. Old versions stay loadable through explicit migrations, because a released save format is a compatibility contract. The save also stores the state of the seeded random generator, so a loaded Campaign plays out the same way it would have. (This first said "the random seed"; the seed alone would only replay the Campaign from its start, so the format stores the generator as it stands when saved.)

In the desktop app (ADR-0010), Save opens the operating system's save dialog and Load its open dialog, filtered to `.moonbase` files, in place of the download and the file picker. The save suggests the same file name, and both dialogs start in the folder last used, which the app keeps in its user-data folder; that is the only thing it keeps, never a save. The page can't reach the file system: it asks the main process to save or open through a narrow bridge, and the main process writes or reads only the file the player chose. The format is the same in both, so saves move freely between the browser and the desktop app.
